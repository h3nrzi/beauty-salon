# Stitch Review 18 — Contact old-version assessment

**Reviewed:** 2026-10-10  
**Source:** `stitch_salon_visual_baseline (15).zip`  
**Purpose:** Review the existing Contact page before refinement.

## Current page structure

The old Contact page has a useful desktop information architecture:

- public header/navigation;
- hero/title area;
- current-status card;
- location/address card;
- phone/contact card;
- opening-hours card;
- map/directions panel;
- written access directions;
- booking CTA;
- salon-space / waiting-area card;
- policy/courtesy block;
- public footer.

This is a good contact-page skeleton. It should be simplified and grounded rather than replaced with a sparse page.

## What should be preserved

### 1. Contact information hierarchy

Preserve clear separation between:

- location;
- contact path;
- opening hours;
- directions.

These are exactly the core purposes of Contact.

### 2. Map / directions area

A large visual directions area is useful.

Keep a map/location placeholder and written direction summary, but do not freeze a specific map provider or real address yet.

### 3. Booking path

Keep a clear `رزرو نوبت` CTA.

Do not turn Contact into a booking workflow itself.

### 4. Desktop two-column density

The old page uses the desktop canvas well.

Preserve a balanced information-rich layout rather than making the page sparse.

## What should improve

### 1. Exact fictional business facts

Current page includes:

- exact Zafaraniyeh address;
- exact phone numbers;
- exact opening hours;
- “north Tehran” positioning;
- named local street directions.

These are not approved salon facts.

Use clearly neutral placeholders until real business data is supplied.

### 2. Dynamic “open now / active” state is not a default baseline

The page shows:

- `پذیرش فعال است`;
- a specific phone-response-until time.

That is a time-dependent state and should not be frozen into the default Contact baseline.

Use a static contact-information presentation.

### 3. Unsupported facilities claims

Current page claims:

- private elevator;
- private parking;
- guest parking;
- exclusive waiting area / guest lounge.

These are unsupported business/facility facts.

Remove them from the refined baseline unless real data is later supplied.

### 4. “Special line / support” product semantics are invented

Current page uses:

- `خط ویژه نوبت‌دهی`;
- `پشتیبانی و هماهنگی`.

The product only needs a contact path.

Use neutral labels such as:

- `تلفن سالن`;
- `راه ارتباطی`.

Do not imply support-center or special-line capabilities.

### 5. Map provider should not be frozen

The old page visibly uses a real-map screenshot.

The refined visual may keep a map placeholder, but do not make Google Maps or any provider an architectural/product decision in Stitch.

### 6. Access-direction copy is over-specific

Current directions mention exact intersections, landmarks and parking behavior.

Use neutral placeholder direction copy.

### 7. “Peace/privacy policy” block is too restrictive and claim-heavy

Current page says:

- entry without coordination is not permitted;
- special privacy/quiet rules.

This creates operational policy that has not been frozen.

Replace with a simple contact/visit note, for example:

- book before visiting for services;
- contact the salon for access questions.

Do not create access-control policy.

### 8. Exclusive waiting-area block is unsupported

The current `آرامش اختصاصی شما` block implies a dedicated private guest lounge.

Remove this claim or replace it with a neutral salon-atmosphere image/supporting text.

### 9. Footer contains the same stale fictional business facts

Use the frozen neutral public footer established on Home / Services / Specialists / Gallery / About.

## Refinement target

The refined Contact page should combine:

- **old Contact** for information architecture and useful desktop density;
- **frozen Home/About** for public visual language;
- **frozen public footer** for neutral business-data placeholders.

The result should be a clear practical Contact page for one salon — not a luxury-access page, support center, facility showcase, or dynamic “open now” dashboard.
