# Stitch Prompt 06 — Gallery page

Design the **Gallery page** for the existing Persian/RTL brand **آرا**, using these frozen visual references:

- `ara-home-soft-editorial-v1`
- `ara-services-soft-editorial-v1`
- `ara-specialists-soft-editorial-v1`

Do not redesign the visual system. Extend the same Soft Editorial language.

## Product purpose

The Gallery is a public visual portfolio of salon work.

Its job is to build trust through curated imagery and help customers move naturally toward:

- relevant Services;
- Specialists;
- Booking.

It is **not** a social-media feed and **not** a reviews/ratings surface.

## Visual continuity

Carry forward:

- Persian/RTL-first layout;
- warm ivory / taupe surfaces;
- restrained terracotta primary actions;
- editorial whitespace;
- subtle borders/elevation;
- natural, refined photography;
- same header/navigation behavior;
- clear «وقت‌های من» access;
- prominent «رزرو وقت» CTA.

Use **سالن زیبایی بانوان آرا** positioning only.

Do not introduce spa, clinic or atelier positioning.

## Page structure

### Intro / page header

Include:

- title such as «گالری آرا» or «نمونه‌کارهای آرا»;
- concise copy explaining that the gallery presents selected visual work from the salon;
- a clear path to Services and Booking.

Do not claim:
- “unfiltered”;
- guaranteed results;
- awards;
- certificates;
- clinical outcomes;
- “best in city” status.

### Curated gallery

Create a visually rich but controlled portfolio.

Use representative categories such as:

- مو / رنگ و استایل;
- میکاپ;
- ناخن;
- non-clinical beauty care where visually appropriate.

The layout may use:

- editorial masonry;
- asymmetric grids;
- alternating large/small image placements;
- restrained category filtering if it improves exploration.

Do not turn the Gallery into an Instagram-like feed.

Avoid:

- likes;
- comments;
- follower metrics;
- timestamps;
- user handles;
- review stars.

### Image detail / context

Each gallery item may communicate concise context such as:

- service category;
- service name;
- specialist name where useful;
- short neutral caption.

Do not invent client identities.

Do not add unsupported claims about outcomes, durability, medical effects or product materials.

If a specialist is referenced, the relationship must be consistent with the Specialists/Services sample data used in the exploration.

### Filtering

A small filter set is allowed if it remains editorial and useful.

If used:

- include an “all” state;
- keep categories simple and product-relevant;
- selected state must not rely on color alone;
- all work must remain discoverable if enhancement is unavailable.

Do not create a complex taxonomy or marketplace filter system.

### Booking / discovery bridge

Provide a clear transition from Gallery into the product:

- view related service;
- view specialist where relevant;
- start booking.

Do not design online payment.

### Final CTA

End with a strong but calm CTA such as:

- «خدمت موردنظر خود را پیدا کنید»
- «رزرو وقت در آرا»

Reinforce:
- transparent time/price in Services;
- pay at salon;
- customer can choose a specialist or «هر متخصص در دسترس».

## Responsive behavior

Provide:

1. mobile Gallery around 390 px CSS width;
2. desktop Gallery around 1440 px CSS width.

Mobile should not become a tiny desktop masonry grid.

Use a deliberate stacked/editorial mobile composition with touch-friendly filters and links.

## Accessibility

Target WCAG 2.2 AA for primary interactions.

Show:

- visible keyboard focus;
- meaningful image alt-text intent;
- category/filter labels;
- selected state not conveyed by color alone;
- readable captions without low-contrast overlays;
- keyboard-usable controls.

If text overlays images, ensure reliable contrast. Prefer captions outside imagery when contrast is uncertain.

## Media boundary

All imagery is **prototype/reference media only** at this stage.

Do not imply image rights are cleared.

Production acceptance requires explicit rights-cleared or owned media.

Do not use the visual result as proof that the pictured work belongs to the salon.

## Product boundaries

Do not add:

- reviews/ratings;
- testimonials as gallery records;
- social feed mechanics;
- likes/comments;
- marketplace/multiple salons;
- multiple branches;
- medical/clinical claims;
- packages;
- online payment/deposit;
- loyalty;
- staff/admin tools;
- architecture/API/storage decisions.

## Content truth

Names, service labels and image captions are fixture data unless separately approved.

Keep copy neutral and grounded.

## Output

Return:

- mobile Gallery screen;
- desktop Gallery screen;
- any design-system delta needed specifically for gallery grids, filters, image captions and focus states.

The Gallery should feel like the natural visual-proof extension of the frozen Home/Services/Specialists system, not a new art direction.
