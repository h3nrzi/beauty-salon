# Stitch Prompt 03 — Refine Home default state

Refine the **Home / خانه** page only.

This is the first page-by-page refinement pass after the whole-product visual system was established.

## What to select in Stitch

Select:

1. the current **Home / خانه** baseline screen;
2. the current **Services / خدمات** baseline screen as a desktop visual anchor.

The Services screen is reference-only.

Return **one Home screen only**.

## Goal

Create a strong **desktop/default Home page** for آرا while preserving the established visual system.

Do not create states or responsive variants yet.

Do not redesign the visual language.

## Visual continuity

Carry forward the existing system:

- Persian / RTL;
- warm ivory/off-white canvas;
- muted terracotta / rose-brown accent;
- warm espresso text;
- editorial heading treatment;
- subtle borders and shadows;
- medium radii;
- calm natural photography;
- controlled whitespace;
- restrained premium tone.

Use the selected Services page as a reference for:

- desktop content width;
- public header/navigation scale;
- button styling;
- typography scale;
- card treatment;
- footer language.

Do not copy the Services page layout.

## Home structure

Build a deliberate editorial desktop composition with these sections:

### 1. Hero

Purpose:
- establish آرا quickly;
- communicate that it is one women's beauty salon;
- make booking obvious.

Include:
- concise Persian headline;
- short supporting copy;
- primary `رزرو نوبت` CTA;
- secondary path to services if useful;
- one strong natural salon/beauty image.

Avoid oversized decorative hero text that pushes useful content too far below the fold.

### 2. Short salon introduction

A concise editorial section that explains the positioning without unsupported claims.

Do not use:
- spa positioning;
- medical/clinical language;
- certifications;
- “best materials” claims;
- years-of-experience claims unless clearly placeholder.

### 3. Selected services

Show approximately 3 selected placeholder services.

Each should support:
- service name;
- short neutral description;
- duration;
- price;
- path to Services / Booking.

Use the same service-card grammar as the wider product.

### 4. Selected specialists

Show approximately 3 placeholder specialists.

Use:
- portrait;
- name;
- neutral expertise;
- path to Specialists / Booking.

Do not show:
- ratings;
- reviews;
- senior/master hierarchy;
- certificates.

### 5. Selected gallery work

Create an image-led editorial strip/grid using a small curated set of work.

Do not make this a social feed.

### 6. Trust / product benefits

Keep this grounded in the actual product experience.

Good themes:
- transparent service duration and price;
- choose a specialist or find an available one;
- clear appointment scheduling;
- manage upcoming appointments.

Avoid unsupported salon-quality, health, hygiene, material or certification claims.

### 7. Final booking CTA

Create a simple strong closing CTA to `رزرو نوبت`.

### 8. Footer

Keep the existing public footer family.

## Content rules

Use neutral fictional placeholder names/data.

Do not introduce:

- multiple branches;
- loyalty;
- reviews/ratings;
- online payment/deposit;
- CRM;
- spa/clinic positioning;
- medical treatment claims;
- organic/certification claims;
- unsupported business facts.

## Required output

Return exactly:

- one refined **Home — desktop/default** screen.

Do not generate:
- mobile;
- tablet;
- loading/error/empty states;
- booking states;
- alternate Home variants.

We will review and freeze the Home default state before moving to Services.
